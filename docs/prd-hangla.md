## 一、定位、目标用户、与 tiermaker 的差异点

### 1.1 一句话定位

`/hangla` 是「我推的格子」主站旗下的**第二个小工具**：把 Bangumi 上的角色 / 动画 / 漫画 / 书籍 / 游戏（统一用图片代表），拖进从「夯」到「拉」的 5 个层级里，生成一张**可导出分享的排序榜**。副标题：「**从夯到拉的排序头脑战（致敬辉告）**」——把「排序」包装成辉夜大小姐式的「头脑战」，玩梗、有记忆点。

### 1.2 它和主站的关系（必须让用户一眼看穿）

同一作者、同一网站、同一套调性、互相导流。**不是独立产品，也不是主站里嵌的第三方工具**——是「我推的格子」做的第二个玩法。全部落地细节见 §8「品牌一致性与家族感」。

### 1.3 目标用户

- **主：** 二次元 / 追番 / 游戏玩家，喜欢在社交平台晒「我的喜好」，愿意做成分表、排榜这类轻创作。
- **次：** 被分享图吸引、第一次点进来的人——他们大概率是上面的同类，看到一张别人的榜会想「我也要排」。
- **特征：** 手机为主、无登录心智、低门槛动手、爱玩梗（夯 / 拉 / 人上人这类黑话有共鸣）。

### 1.4 与 tiermaker 的差异点

| 维度 | tiermaker | /hangla |
| --- | --- | --- |
| 物品来源 | 自定义上传为主 | **全部来自 Bangumi**（角色/动画/漫画/书籍/游戏），搜索即得，不用自己找图 |
| 移动端体验 | 拖拽为主，小屏「有点费劲」（竞品普遍承认） | **点选 + 底部托盘 + 点层级**，拇指可达、零长按、零误触（见 §4） |
| 品牌与中文语境 | 英文通用站，无中文黑话 | 层级用中文黑话（夯/顶级/人上人/NPC/拉完了），天然中文社交语境 |
| 分享闭环 | 通用分享 | **针对微信/QQ 做了图片承载入口**（品牌+短链+二维码，链接可被拦但图能过） |
| 登录 | 需注册/登录 | **无登录**，打开即用 |
| 家族 | 独立产品 | **主站第二个工具**，双向往返、共享品牌 |

## 二、核心用户场景（≥3，标注手机场景）

### 场景 1：追番党晒「本季最爱」（动机：我只想发个图）

手机。新番季结束，打开 /hangla → 搜「本季新番角色」→ 把 30 个角色排进 5 层 → 导出 1:1 图 → 长按保存 → 发朋友圈/小红书。**目的就是一张能发的图，全程 2~3 分钟。**

### 场景 2：被朋友分享的榜种草，立刻做一张同款（动机：我想快速做一张）

手机。朋友发来一张「夯拉榜」→ 我扫码 / 输入短链打开落地页 → 点「我也要排」→ 零输入，同一批物品已在 → 我改两层、加个「人上人」→ 导出我的版本 → 发回去。**不登录、不找图、不重新搜索。**

### 场景 3：把「心中神作」排个名（动机：我想快速做一张 + 深度一点）

手机。想排「近几年最佳动画」→ 搜 动画 → 搜到几十部 → **批量多选**丢进候选池 → 逐个放进层级 → 层内拖拽微调顺序 → 导出并生成短链 → 分享到 QQ 空间。**核心痛点是批量与层内重排，移动端必须有顺手方案。**

### 场景 4（次要，桌面）：做一张大型榜

桌面。排 80~100 个游戏 → 鼠标拖拽增强（见 §4.8）→ 导出宽幅图。**桌面不是验收重点。**

## 三、信息架构与页面结构（手机优先 · 四段式底座）

> 手机页是一个干净的**四段式竖排**，从上到下依次：**品牌主视图 → 操作区/预览区（合一）→ 按钮区 → 底部区**。「先把基础底座做对」，各段职责互不越界。

```
oshigrid.me/hangla（手机优先 · 四段式底座）
┌─ PART 1 · 品牌主视图（日系：主 logo 原体 + 副题，见 §8.2）
│   ├─ 【我推的格子】主站 logo（原体保留，与主站完全一致，不改）
│   └─ 其下小字副标题：从夯到拉的排序头脑战
│   ── 经典日系排版：大号标题ロゴ + 下方小号サブタイトル
│
├─ PART 2 · 主要操作区 = 预览区（合一的同一区，所见即所得）
│   ├─ 层级行区（既是预览也是操作，拇指可达，屏幕主体）
│   │   ├─ 层级行（N 行：层级色块 + 名称 + 行内物品缩略图横排）
│   │   └─ 层级行可：改色 / 改名 / 增删 / 上移下移
│   ├─ 候选池 / 搜索（附加面板，可唤出取物：五类 tab + 勾选入池）
│   └─ 底部托盘（选中物品临时区，点选投放核心，见 §4）
│
├─ PART 3 · 按钮区（拇指可达，固定于操作区之下）
│   ├─ 第一个大按钮：【导出】（保存图片 / 生成短链）
│   └─ 下方次按钮：设置 / 重置 / 层级管理 / 撤销 · 重做
│
└─ PART 4 · 底部区（Footer：社交 / 数据来源 Bangumi /
    致敬 itorr · anime-grid / 免责声明 / /netcheck 与 /hangla 互推）
```

**四段职责约定：**

- **PART 1 只管品牌与身份**，不承载操作；点 logo/站名回主站首页。
- **PART 2 是主体**：层级行区即预览即操作，用户的眼睛始终停在排榜结果上；搜索/候选池、托盘都是为它服务的附加面板。
- **PART 3 是动作出口**：导出是第一大按钮，其余低频动作（设置/重置/层级管理/撤销）排在后面，不抢首屏视觉。
- **PART 4 是 Footer**，复用主站 + 互推入口。

**路由新增：**

- `/hangla`：分站主编辑页
- `/h/:id`：榜单分享落地页（复用 `/t/:id` 的短链范式）
- `/netcheck`、`/` 等主站路由保持不变

## 四、⭐ 手机端排序交互设计

> 目标（宗旨 1 的判定标准）：**从打开页面到排完 30 个物品，全程只用一根拇指、不需要看教程、不会误触。**

### 4.1 三条设计底线

1. **不默认用 HTML5 拖拽**——它在触屏上不支持/难用，竞品普遍承认「拖拽在小屏上费劲」。
2. **主操作全在拇指可达区**：层级行 + 底部托盘放屏幕下半区。
3. **没有长按门槛、没有误触风险**：点选是唯一确定性操作；拖拽只留给「层内重排」这一短距微调场景。

### 4.2 三种候选交互方案对比

| 方案 | 完成步骤 | 单手可达 | 误触风险 | 与长列表滚动冲突 |
| --- | --- | --- | --- | --- |
| **A. 点选 → 底部托盘 → 点层级** | 点物品(1) → 点层级行(2) = **2 步/物**；多选可批量 | 高（都在拇指区） | **低**（无长按、无拖拽） | **无**（无拖拽手势） |
| B. 点选 → 底部弹层列层级 → 选一个 | 点物品(1) → 弹层出现 → 点层级(2) | 中（弹层遮挡列表） | 中（弹层需关闭） | 低 |
| C. 长按拾起 + 拖拽 + 边缘自动滚动 | 长按(~300ms) → 拖到目标层 → 松手 | 中（跨层距离长、费力） | **高**（与滚动冲突、易误拾起） | **高**（需 delay + 滚动阈值 + 边缘滚动） |

**推荐：方案 A 为主交互。** 理由：

- 全程 2 次点按、拇指可达、零长按、零误触、与页面滚动零冲突——最符合宗旨 1；
- 竞品（tiermaker 系、tierlist-maker 等）在移动端普遍采用或兜底「tap 选择 → tap 层级」的交互，已被验证；
- **C 只保留给「层内重排」这一短距场景**（同一行内距离短、属于微调，拖拽手感反而更好、无需托盘）。

### 4.3 四个核心动作的完整流程（手机）

**① 入层（放入某层）**

1. 拇指点候选池里某个物品 → 该物品缩略图**瞬时落入底部托盘**（高亮，表示已选中）。
2. 点目标层级行（行的任意位置）→ 物品落入该层**行尾**，层级计数 +1，卡片弹一下。
→ **2 次点按完成 1 个物品。** 连续放多个 = 重复这两个动作；托盘保持上一个物品，方便连续投放。

**② 层内重排（同一层内调顺序）**

1. 在该层行内，长按某个物品（≈300ms）→ 物品「浮起」。
2. 在同一行内拖到目标位置 → 松手落入。
→ 短距拖拽，拇指舒适；拖拽时禁止页面滚动与下拉刷新（见 §4.6）。

**③ 跨层移动（从 A 层换到 B 层）**

1. 点 A 层里某个物品 → 缩略图进托盘。
2. 点 B 层层级行 → 物品从 A 层**移除**、落入 B 层行尾。
→ **2 步，等价于「入层」**，用户心智统一。

**④ 移出回候选池（把物品丢出榜）**

1. 点某层里某个物品 → 缩略图进托盘。
2. 点托盘上的「回候选池」按钮 → 物品从层内消失、回到候选池。
→ **2 步。**

### 4.4 批量操作（摆 20~30 个时是刚需，必须给方案）

- **托盘多选模式**：托盘右侧「多选」开关 → 进入多选 → 连续点选多个物品（来自候选池或层内）→ 点一个层级 → **一次性全部落入该层**。
- **搜索批量加入**：搜索结果列表每项带勾选框，可「勾选 → 加入候选池」批量导入。
- 预期：摆 30 个，用批量能在 1 分钟内铺完。

### 4.5 撤销（误触是移动端常态）

- **入口**：工具栏固定「撤销」按钮（+「重做」），同时提供**抖动/摇一摇撤销**（可选）。
- **回溯范围**：最近 **20 步**内的放置 / 跨层 / 移出 / 改名改色 / 增删层，全部可撤销。
- **层级级联**：撤销「删除层级」时，该层物品回到候选池，不丢失。
- 提供「清空某层」需二次确认（防误触一键清空）。

### 4.6 触控细节（具体到可验证）

| 项 | 规格 |
| --- | --- |
| 最小点击目标 | 物品视觉 ≥ 48px；**命中热区放大到 ≥ 56px**（视觉 48、热区 56） |
| 层级行高度 | ≥ 64px（含色块 + 名称 + 缩略图），可点按 |
| 拇指可达区 | 层级行区 + 底部托盘固定在屏幕下半区；搜索/候选池在上半区，不参与高频操作 |
| 拖拽时阻止滚动 | 长按/拖拽期间 `touchmove` 上 `preventDefault()`，且容器 `overscroll-behavior: none`，禁用下拉刷新 |
| 命中判定放大 | 相邻物品间距 ≥ 4px；点按命中按热区 56px 判定 |
| 反馈动效 | 落入层级：卡片弹跳 + 该层计数 +1；误触判定：点按 120ms 内位移 < 10px 视为 tap，否则视为滚动 |
| 触觉/视觉 | iOS 可选 Haptics；Android 用 `navigator.vibrate(10)` 做落入反馈（可开关） |

### 4.7 候选池获取（五类 + 本地）

- **搜索 Bangumi**：类型 tab（角色 / 动画 / 漫画 / 书籍 / 游戏）→ 走 `/api/search` 代理（`searchMode: character / subject` + subject `type` 过滤）。
- **批量上传本地图片**：一次选多张，进候选池（不入 Bangumi，仅本地）。
- **粘贴图片链接**：粘 URL → 校验 → 进候选池。
- **搜到一堆后快速多选**：结果列表勾选 → 「加入候选池」。

### 4.8 边界态

| 状态 | 处理 |
| --- | --- |
| 空候选池 | 居中引导：搜索框高亮 + 「搜一部番 / 传几张图」两个主入口，配玩梗微文案 |
| 只有一个物品 | 物品直入托盘，正常投放 |
| 某层已满（若设单层上限） | 该层行尾出现「已满」，提示换层或移除 |
| 达到总上限（100） | 提示「再排要超了，建议分两张榜」，禁止继续加，导出走降级模式 |
| 图片加载失败 | 灰色占位图（带斜线），点重试；经 `/api/img` 代理加载仍失败则保留占位 |

### 4.9 桌面端（次要，不作为验收重点）

- 鼠标增强：支持纯鼠标拖拽（HTML5 DnD 或 SortableJS 的鼠标模式）、拖拽越过层级行边缘自动落到相邻层。
- 保留与手机一致的点选投放作为兜底；桌面只在「大型榜 + 鼠标」场景下强调拖拽。

## 五、功能列表 P0 / P1 / P2（每条写「用户能做什么」）

### P0（上线必须有）

- 用户能看到 5 个默认层级：**夯 / 顶级 / 人上人 / NPC / 拉完了**（顺序、名称固定）。

- 用户把物品放进层级（点选 → 托盘 → 点层级）。

- 用户把一个物品从 A 层移到 B 层。
- 用户把一个物品移出层级、回到候选池。
- 用户批量多选多个物品一次性丢进同一层。
- 用户撤销 / 重做最近 20 步。
- 用户修改某个层级的名字。
- 用户修改某个层级的颜色。
- 用户增删层级（加一层 / 删一层；删层时物品回候选池）。
- 用户导出图片（默认 1:1，iOS 长按保存 / 桌面下载）。
- 用户生成分享短链，落地页能被他人打开并看到这张榜。
- 用户从落地页一键「我也要排」（做同款，零输入开排）。

### P1（上线后第一梯队）

- 平台预设导出尺寸一键切换（朋友圈/小红书 3:4、微博 3:4、QQ 空间 1:1、X 4:5）。
- 「热门」入口：按做同款次数排的小榜单列表。

## 六、⭐ 传播闭环设计

### 6.1 闭环图 + 流失点 / 对策

```
制作 → 导出图/短链 → 发平台(微信/QQ/微博/X) → 他人看到 → 落地页 → 「我也要排」→ 制作 → …
│        │流失①             │流失②            │流失③            │流失④
▼        ▼                   ▼                  ▼                  ▼
对策①   对策②               对策③              对策④               对策⑤
```

| 环节 | 流失点 | 对策 |
| --- | --- | --- |
| 制作完成 | ① 不知道怎么存/没导出 | 导出 CTA 醒目；iOS 明确「长按保存到相册」，给一次引导 |
| 发平台 | ② 图太大/尺寸不适配 | 平台预设尺寸一键切换 |
| 他人看到 | ③ 不知道是什么；微信/QQ 链接被拦 | 图上带**品牌名 + 可手动输入的短链 + 二维码**；图片一定能过，链接不保证（见 §6.2） |
| 落地页 | ④ 不知道能做什么/还要登录 | 首屏直接「我也要排」，**零输入做同款**，无登录 |
| 做同款 | ⑤ 默认榜与意图不符 | 做同款后可改层级/删改，与「从零开始」并存 |

### 6.2 ⚠️ 微信/QQ 关键约束（必须处理）

- **现状：图片能过，链接不一定能过。** 微信对外链有《外部链接内容管理规范》，新域名/未验证域名可能弹「停止访问/风险提示」；QQ 类似。
- **因此：导出的图片本身必须承载入口**——用户在微信/QQ 里看到一张图，即便链接被拦，也能靠图上的信息进来。

**导出图片页脚/角落的具体布局（品牌承载区）：**

```
┌────────────────────────────────────────────┐
│                   榜 图                     │
├────────────────────────────────────────────┤
│  [logo]【我推的格子】   oshigrid.me          │  ← 左：主站 logo + 主站域名
│  从夯到拉的排序头脑战                       │  ← 副标题（品牌区小字）
│                                            │
│  oshigrid.me/h/AbCd      [二维码]           │  ← 右：可手动输入的短链 + 二维码
└────────────────────────────────────────────┘
```

- **为什么放右下角+左下角、且不惹人烦**：和主站导出图的品牌区同一位置与样式（用户已熟悉），放在内容下方、不遮挡物品；二维码固定大小、短链极短（`oshigrid.me/h/AbCd`），一眼可读。
- **为什么保证被看见**：品牌区高度固定、主色高亮「【我推的格子】」，与主站导出同款视觉——用户扫一眼就认识这是「我推的格子」的产出。

### 6.3 图片上的家族品牌（同时服务两个目标）

一张榜被分享出去，既要让人想打开分站，也要让人认识主站：

- **品牌区左侧**：logo + 【我推的格子】（主站 logo 原体）+ 副标题 + **oshigrid.me（主站域名）** → 一眼认识主站。
- **品牌区右侧**：本榜落地页短链 + 二维码（指向 `/h/AbCd`）→ 打开分站做同款。
- **优先级**：**当前这张榜的落地页短链 = 主入口**（扫码/输入直达做同款）；**主站域名 = 品牌背书次入口**（让人认识主站、可在落地页再点进主站）。两者共存不冲突。

### 6.4 一键「做同款」——闭环最重要一环

- 落地页首屏：榜图 + 大按钮 **「我也要排」**。
- 点「我也要排」→ **零输入**：同一批物品（含原层级分布）预填充进编辑页 → 用户直接改/加/减 → 导出自己的版本。
- 与「从零开始」并存：落地页同时给「新建榜单」入口（小按钮），两个都不阻断。

### 6.5 链接的社交卡片（OG）——技术决策

- **问题**：静态 OG 无法按每张榜变化。
- **推荐方案：创建时预生成封面快照（低成本）**。用户在「保存并分享」时本来就要在本地 canvas 渲染导出图——把这张 PNG 上传到 R2/对象存储，返回 URL 存进 D1，作为 `og:image`。`og:title` = 「有人把 30 个角色排了张榜，你也来排」+ 分站名。
- **备选**：每个请求动态渲染（worker 无头生成 PNG）——成本高、失败面大，**不推荐本期**。
- **降级**：快照生成/上传失败 → 用主站默认 OG 卡（`og:image` 指向主站 logo），预览不美但**认得出来是「我推的格子」**。
- **预期生效**：微博 / X / 部分 IM 认自定义 OG；微信/QQ 的卡片预览支持有限，因此**入口兜底仍是图上二维码/短链**（§6.2）。

### 6.6 平台预设导出

- 默认 **1:1**；一键切换：朋友圈/小红书 **3:4**、微博 **3:4**、QQ 空间 **1:1**、X **4:5**。
- 切换即时预览比例；导出按所选比例裁切画布（不裁剪物品，等比缩放）。

### 6.7 落地页 CTA（首屏不滚动可见）

- 按钮候选：「我也要排」/「抄一份来排」/「用它排个我自己的」/「复制这份榜，你来排」。
- **推荐「我也要排」**：与「从夯到拉的排序」玩法呼应、主动性强、一听就懂。

### 6.8 回访钩子

- 落地页与编辑页的「热门」入口（P1）：按**做同款次数**排的小榜单，复用主站 `snapshot_cache` / trending 的思路。

### 6.9 衡量指标（只定义，不写埋点实现）

| 指标 | 定义 |
| --- | --- |
| 导出率 | 进入编辑态 → 成功导出一张图 的比例 |
| 扫码/短链进入率 | 落地页 UV / 图片曝光（估算） |
| 二次创作率 | 打开落地页 → 完成「做同款」的比例 |
| 分享后回访率 | 落地页 UV 中再次打开同一榜的比例 |
| 分站 → 主站跳转率 | 落地页点 logo/主站域名进入主站的比例 |
| 主站 → 分站开通率 | 主站用户首次进入 /hangla 的比例 |

### 6.10 滥用与配额防护

- **短链不可枚举**：落地页 ID 用 128bit 随机短码（不可顺序猜测）。
- **他人榜单不可改**：落地页只读；「做同款」是复制到本地编辑，**不写回原榜**。
- **单榜 / 每日创建量上限**：按 `user_hash`（复用 `save.ts` 的 IP+盐哈希）限每日创建 N 条；单榜物品数硬顶 100。

## 八、导出与分享细则

### 8.1 格式与尺寸

- 格式：**PNG**（透明背景不需要时可 JPEG 降体积，P1）。
- 默认 1:1；平台预设：朋友圈/小红书 3:4、微博 3:4、QQ 空间 1:1、X 4:5。
- 导出画布像素：短边 ≥ 1080px（高清够社交）；大榜（>30 物品）用「逐层分块 → 合成」保证成功率（§11）。

### 8.2 手机上如何保存

- **iOS Safari**：**长按图片 → 「存储图像」**（非下载），首页给一次引导提示。
- **Android**：长按 → 保存 / 下载。
- 桌面：`<a download>` 下载。
- 均无需登录。

### 8.3 链接形态与有效期

- 短链：`oshigrid.me/h/AbCd`（128bit 随机短码）。
- **有效期**：落地页数据**不设硬过期**（长期可访问），但启用「空闲清理」：仅无人访问的旧榜可被清理（P2）。榜单快照（og:image）设较长缓存。

### 8.4 链接不可用时的降级

- 微信/QQ 拦截或弹警告 → 图上的二维码 + 可手动输入的短链是兜底（§6.2）。
- 短链 404 / 被清 → 落地页给「回到主站」入口 + 提示「这份榜可能被清理了」。

## 九、数据模型

> 字段级。**不登录**，本地为主、服务端少量。

### 9.1 本地存储（localStorage / IndexedDB）

```
hangla_local_board: {
  version: 1,
  title: string,                    // 榜名（默认空）
  tiers: [{ id, name, color, order }],  // 层级配置（可改名/改色/增删/排序）
  items: [{                          // 排好的物品
    id, tierId|null,                // 层级归属（null=候选池）
    tierOrder,                       // 层内顺序
    name, imgUrl(经/api/img代理), 
    bangumiId, category, subjectType
  }],
  meta: { createdAt, updatedAt }
}
```

- 输入防抖保存到 localStorage，IndexedDB 做候选池大图缓存。

### 9.2 服务端存储（D1，推荐新表 `hangla_boards`）

```
hangla_boards {
  id            TEXT PRIMARY KEY,   // 128bit 随机短码
  title         TEXT,
  config        JSON,               // 完整榜（tiers + items 顺序）
  user_hash     TEXT,               // 创建者（IP+盐哈希，复用 save.ts 范式）
  device_type   TEXT,
  created_at    INTEGER,
  og_image      TEXT,               // 封面快照 URL（§6.5）
  made_again    INTEGER DEFAULT 0   // 被做同款次数（社交证明/热门排序）
}
```

- 复用现有 `saves`/`save_items` 的隐私化（不存 IP 原文、不存 Base64 图）。

### 9.3 物品类别映射（Bangumi）

- 角色 → `searchMode: character`
- 动画 / 漫画 / 书籍 / 游戏 → `searchMode: subject` + subject `type` 过滤
- **注（映射小坑）**：Bangumi 的 `type=1`（书籍）同时包含漫画与书籍，`type=4` 为游戏、`type=2` 为动画、`type=3` 为音乐。五类里的「漫画」与「书籍」需一个轻量映射（如按平台/tag 细分，或本期合并为「书籍·漫画」一类）。**此项留待实现确认，不阻塞 PRD。**

## 十、性能与容量边界

| 项 | 边界 / 策略 |
| --- | --- |
| 物品上限 | 默认 30、硬顶 100；>30 提示可继续但导出走降级 |
| 图片压缩 | 候选池缩略图压到短边 300px（≈30~60KB）；导出用原代理图 |
| 移动端内存 | 30 张图全量进内存 ≈ 3~5MB；导出 canvas 短边 1080，30 张内单次绘制 |
| 导出策略（大榜） | >30 物品：**逐层分块渲染 → 合成**，避免单张超大 canvas 内存爆掉；iOS 内存上限触发时自动降为分块 |
| 低端机降级 | 内存/性能检测（`navigator.deviceMemory` / UA），自动关 Haptics、缩物品缩略图、导出降为 JPEG |
| 图片加载 | 全部经 `/api/img`（缓存一年、20s 回源超时）；失败占位 + 重试 |
| 跨域污染 | 同源代理 → 无跨域 taint；仍对 `crossOrigin='anonymous'` 兜底（复用 canvasDraw 既有做法） |

## 十一、视觉与设计语言

### 11.1 5 个默认层级配色（推荐：顶部粉系递减 + 底部灰系表示平庸/拉胯）

| 层级 | 配色 | 语义 |
| --- | --- | --- |
| 夯（最顶） | `#e4007f`（主色） | 顶中顶，用品牌色 |
| 顶级 | `#ec4899` | 第一梯队（深粉） |
| 人上人 | `#f472b6` | 高于平均（中粉） |
| NPC | `#9ca3af` | 路人、平庸（灰） |
| 拉完了（最底） | `#6b7280` | 拉胯到底（深灰） |

- **理由**：顶部三档用主色粉系递减，守住品牌一致；底部两档用灰系表达「平庸/拉胯」，语义清晰且不引入突兀彩虹色。

### 11.2 token：沿用 vs 新增

- **沿用**：`primary(#e4007f)/hover(#c2006b)/light(#fce7f3)`、`rounded-std/btn/inp`、`btn-primary/outline-primary/outline-gray`、`card-base`、`input-std`、`icon-btn`、`Noto Serif SC`、`tracking-widest`。
- **新增**：`tier-row`（层级行样式，可着色）、`tray`（底部托盘）、`drag-ghost`（拖拽浮起态）、`tier-count`（层级计数徽标）。

## 十二、技术方案概览（只选型与理由，不写代码）

- **前端**：Vue 3 + Vite + UnoCSS（沿用主站）；移动端排序**不默认 HTML5 DnD**。
  - 点选投放（主）：原生 tap 事件 + 状态管理（Pinia），无手势依赖。
  - 层内重排（短距）：**`vue-draggable-plus`（已在依赖）** 底层 SortableJS，配 `forceFallback: true` + `delayOnTouchOnly` + 滚动阈值，规避触屏滚动冲突。
- **图片**：**必用 `/api/img` 同源代理**，绝不同源直连 `lain.bgm.tv`。
- **搜索**：复用 `/api/search`（鉴权 + 1h 缓存），补 subject type 过滤。
- **导出**：复用 `canvasDraw.ts` 链路；大榜分块合成；封面快照上传 R2 供 OG。
- **后端**：Cloudflare Pages Functions + D1；短链存取 + 做同款读取 + 配额（user_hash）。
- **部署**：与主站同域同构建，无新增域名。
